# When to use it

Use FAQ schema when a page genuinely contains a list of questions and answers that serve users, such as a real FAQ section addressing common questions about a product, service, or topic. Do not use it on content that is not actually a question-and-answer format, and do not invent FAQs solely to add markup.

## Where it fits

FAQ schema fits a page that really has frequently asked questions and their answers: a product FAQ, a support page answering common questions, a topic page that addresses the questions people actually ask. The content exists for users first, and the schema describes it. When you have genuine Q&A content, marking it up helps engines understand and use it, which is exactly the case the schema is for.

## Match the schema to real content

The markup should reflect questions and answers that visitors actually see and benefit from on the page. If the page has a visible FAQ section, marking it up is appropriate. The test is whether the Q&A content is real and user-facing. Schema added to describe content that genuinely helps users is the legitimate use; schema describing content that exists only for the markup is not.

## Where it does not fit

FAQ schema does not fit content that is not a genuine question-and-answer format. Forcing arbitrary content into fake questions to qualify for the markup misuses it, and engines may disregard or penalize markup that does not match real, useful content. If a page is not actually answering questions for users, it does not need FAQ schema. Use it where the format is real, not as a wrapper to dress up content that is something else.

## Guidelines change

How engines treat and display FAQ markup has changed over time, and the visibility benefits in search results have varied. The durable value is in helping machines understand genuine Q&A content, which supports being matched to questions and cited, regardless of how any particular result display works at a given moment. Use FAQ schema because it accurately describes real, useful Q&A content, not in pursuit of a specific display feature that may change. The honest, content-first use is the one that holds up.
